# Monorepo handoff — read this first in a new session

Branch: `monorepo` was merged to `main` on 2026-10-13 and `main` is now the production branch (the old standalone `dhakal-patro` site is retired). Every push to `main` deploys via GitHub Actions → `scripts/deploy.sh`. See `docs/PRODUCTION-PLAN.md` for the server, Redis cache and rollback.

Rule the owner set: **web is the source of truth.** Where the website and the app differ, the web version wins and the app adopts it. One copy of anything shared, in `packages/`.

## Layout
`apps/api` (FastAPI) · `apps/web` (React+Vite) · `apps/mobile` (Expo) · `packages/{domain,i18n,design-tokens,icons,api-client}`. npm workspaces + Turborepo, one root lockfile.

Package manager: **npm workspaces** stay. The brief suggested pnpm "where appropriate"; it is not: EAS builds and the VM deploy (`scripts/deploy.sh`) install with npm from `package-lock.json`, and Metro/Expo need extra hoisting config under pnpm's symlinked layout. Switching would touch the iOS build pipeline while a release is in review, for no gain over the current single lockfile.

What each app shares (and what stays per platform):
- **Design values** — `packages/design-tokens` (README): colours/roles/themes, type scales, spacing, radii, shadows, sizes, motion, breakpoints. Web reads generated CSS variables; the app reads typed TS values and a generated Tailwind JSON. UI components stay per platform.
- **Icons** — `packages/icons` (README): which Lucide icon means what, sizes, stroke; web renders lucide-react, the app react-native-svg.
- **API** — `packages/api-client` (README): all request functions, accounts, documents, errors, timeouts, query keys, response contracts; checked against the URL golden and FastAPI's OpenAPI document.
- **Logic and copy** — `packages/domain`, `packages/i18n`.

- `packages/domain` — plain TS shared logic/data, imported as `@vedic-patro/domain/<path>`. Lint (`npm run lint -w @vedic-patro/domain`) allows imports only from the package, `import type` from `@vedic-patro/api-client`, and `clsx`, `tailwind-merge`, `three`, `healpix-ts`. No React / browser / React Native.
- Language and copy: each app calls `configureLocale` once (`domain/locale.ts`); web in `apps/web/src/i18n/index.ts`, mobile in `apps/mobile/lib/i18n.tsx`. Copy lives in `packages/i18n/src/strings.ts` (run `npm run generate -w @vedic-patro/i18n` after editing).
- Learn chapters are data (`domain/src/learn/articles/**`), rendered by `apps/web/src/lib/learn/article-render.tsx` and `apps/mobile/components/learn/article-render.tsx`. Inline markup: `**strong**`, `*teal*`, `~amber~`, `` `num` ``, `[[slug|label]]` link. A literal tilde in prose is written `∼`.

## Checks before every push
```
npx turbo run typecheck
npx turbo run lint --filter=./packages/*      # domain portability, i18n + token output up to date
npx turbo run test --filter=./packages/*      # unit tests, URL golden, OpenAPI contract
npm run check:shared                          # both apps still use the shared client, tokens, icons
npm run build -w @vedic-patro/web             # prerenders 63 pages
cd apps/mobile && npx expo export --platform all --clear
cd apps/api && python scripts/export_openapi.py --check
git checkout apps/mobile/store/assets/feature-graphic.png apps/web/public/sitemap.xml   # regenerated by postinstall/build — never commit them
```
Backend tests (`cd apps/api && python -m pytest -q`) need `data/cities.db` (`python scripts/import_cities.py`, downloads GeoNames) and the Swiss/JPL ephemeris files (`pip install -r requirements.txt` provisions them). Without them, 171 tests fail and 1 errors (1129 pass) — the same set before and after this work.

`npm run lint -w @vedic-patro/web` (eslint) reports 89 problems that predate this work (react-hooks rules); none were added.
Commit trailers: `Co-Authored-By` + `Claude-Session` lines as in earlier commits.

## What stays per app on purpose (not duplication)
Tailwind class tables with different tokens (`patro-classes`, `wheel-classes`, `timeline-classes`, `wheel-svg-classes`); asset/texture loading (`sky-textures`, `nebula-sources`, `hips-config`, `wheel-glyph-art`, `hips-config` (each app sets its own tile base URL)); the 3D sun-earth-moon maths (unit space in the app, pixel space on web); API request modules and storage; React hooks; route tables, icon maps, app-only nav (`panchanga-sidebar-nav`, `related-page-links` paths); mobile-only `panchanga-detail-cells`, `wheel-scrub`, `sait-suitability-style`, `element-routes`, `panchanga-shell-paths`, `bs-range` (1700–2200 picker limits).

## Tools for moving duplicates into domain
`scripts/monorepo-tools/hoist.mts <web file> <mobile file> <domain module> names` moves top-level helpers that are identical in both files, with everything they depend on, and imports them back; it refuses unless the whole closure is the same text in both, has no JSX/hooks and only portable imports. `adopt.mts <file> <module> names` replaces a third copy with the domain one, refusing if any constant the domain copy reads is declared differently in that file. About 80 helpers (~4.7k duplicated lines: 3D sky builders and terrain, learn-diagram geometry, timeline lanes, kundali chart scales, avakahada/vastu wheel geometry, DainikKranti day helpers) moved this way.

Left per app because the two copies differ (review if the behaviour should match): sun-times grid `gregorianMonthLengthsFromData`, kundali section-nav `KUNDALI_SECTIONS`/`dashaSystemFromSection`, vastu `PlotState`, `parseTimeToMinutes` (GhatiClock vs MuhurtaAside), app `DayTimeline.tsx`'s own `ChartSegment`/`minutesOnVedicChart`, the playground EclipticWheel's `COLOR`, `DayPatroCard`'s `phaseOf`, `profileToInput` (types come from each app's auth module).
