# The shared panchanga engine

One calculation engine for the website and the phone app. Both import `@vedic-patro/domain/panchanga/engine/day`
(and `.../blocks`, `.../calendar-blocks`, ...); nothing here is written twice. It runs on the sky (`astronomy/sky.ts`):
positions from the stored Chebyshev file, every boundary solved from them, in the reader's ayanamsha.

Each file follows one Rust builder, so a payload made here is the payload the server makes:

| here | Rust (`apps/rust/crates/panchanga/src`) |
|---|---|
| `blocks.ts` | `daily.rs` anga blocks, `blocks_time.rs` (ritu, ayana, choghadiya, hora) |
| `calendar-blocks.ts` | `lunar_month.rs`, `nepal_sambat.rs`, `samvatsara.rs`, `daily.rs` headers |
| `bala-blocks.ts` | `blocks_bala.rs` |
| `solar-blocks.ts` | `blocks_solar.rs` |
| `lagna-blocks.ts` | `blocks_lagna.rs` |
| `day.ts` | `daily.rs::assemble` (`buildDay`, `DAY_BLOCKS`, `isComplete`) |
| `tables.generated.ts` | name tables, generated by `scripts/gen-panchanga-tables.py` |

`test/engine-day.test.ts` compares every block in `DAY_BLOCKS` with the 113 recorded daily payloads. To port the next
block: translate the Rust builder, add its key to `DAY_BLOCKS`, run that test.

## Done
- All 54 blocks of the daily payload (`buildDay`, `isComplete() === true`), checked against the 113 recorded days.
- The day route's response (`day-response.ts`: `dayState` + `dayResponse`; the app's day shape, `detail`/`slim`/`detail_shared`,
  festivals with details and `festival_saits`, era labels from `era-render.ts`), checked against every recorded day.
- `reference=midnight` (`midnight.ts`) and `civil=true` (`civil-timeline.ts`) day variants, checked against the recorded ones.
- `/panchanga/at-time` (`at-time.ts`: instant tithi/nakshatra/yoga/karana, graha latitude/RA/Dec from the text's shara in
  `surya-formulas.ts`, instant lagna, upagrahas, `muhurta_now`).
- `/panchanga/year/{y}/sun` and the year wheel (`year.ts`).
- `/panchanga/elements` and `element/{name}/day|month|spans` (`element.ts`).
- The printable patro month `/nepal/patro/{y}/{m}` (`patro-month.ts`, over the lite month grid and the middle day's header).
- `/nepal/panchak/year/{y}` (`panchak.ts`, with `yearSpanJd` and `stampYear` the other graha year routes will reuse).
- Surya eclipses (`astronomy/surya-eclipse.ts`, wired through `LocalCalendar.eclipse`).
- All of these are reached through `LocalCalendar` (`festivals/local-calendar.ts`) and `fromLocal` in `api-client/src/client.ts`;
  they answer for the Surya Siddhanta at the default place or a known city, and return null (the server answers) otherwise.

Tests: `test/engine-day.test.ts`, `engine-day-response.test.ts`, `engine-at-time.test.ts`, `engine-year.test.ts`,
`engine-element.test.ts`, all against `apps/rust/tests/fixtures/http_golden_*.json` through `test/golden-diff.ts`
(instants within 20 s, clocks within a minute, text by shape).

- The full BS month (`month-full.ts`), AD/BC months, gochar with graha asta/vakri/sthiti (`gochar.ts`), sait
  (list, month, detail, personalize), rashifal with personal and janma (`jyotish/rashifal/engine.ts`), Surya and Drik.
- At-time by a typed date, today or a Julian Day, and by a `datetime=` wall clock (the mobile wheel); the web's
  दिन-रात day (`reference=midnight`).

- Birth charts (`jyotish/kundali/`): `/kundali/detail`, `/kundali/report`, `/kundali/vimshottari`, `/kundali/dasha/expand`,
  `/kundali/milan`, `/shadbala` and `/planetary/positions`, checked against every recorded response in
  `test/engine-kundali.test.ts`. Dasha dates differ from the server's by up to a few hours (the server's Surya Moon still
  steps in 10 s); the device fixes choghadiya-at-birth, which the server reads from a missing weekday key (always Sunday).
